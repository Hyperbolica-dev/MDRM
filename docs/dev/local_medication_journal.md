# 助眠药物扰动与本地日志设计

日期：2026-10-05。状态：v1.3 已实现最小本地名称库与追加日志；下述完整关联、归档、更正及导出机制仍为后续设计。

## 已确定的输入契约

`sleep_medication` 是“助眠药物扰动”标记。用户只勾选即可完成记录，不追问用药细节，不按未填细节降低记录完整度。它说明有药物介入，不说明药物已导致提前、延后或认知损伤。

不勾选只表示未标记此类扰动，不涵盖所有药物使用。历史导入生成的默认 False 必须与主动填写区别对待；现有 CSV 无法完整区分时，不将其称为“确认未用药”。不回填药名，不从睡眠形态推测药物。

## 极低输入成本的交互

1. 默认路径保持现有一行 checkbox 与常驻提交按钮；用户可以永久只用此路径。
2. 独立的“用药详情（自愿，仅本地）”入口由用户主动打开，不随勾选弹窗。先保存睡眠记录，详情可以随后补写；详情失败不阻止睡眠保存，也不得产生“全部已保存”的假回执。
3. 建库时只需一个本地名称或代号，如“晚间 A”。真实名称、剂型、资料链接均可不填。常用条目靠前显示，停用条目归档，不破坏历史引用。
4. 补写日志时点选条目即可；剂量、时间、途径、备注全部可空。也允许只写匿名事件，不要求先建库。不能自动沿用上次实际剂量或以点击时间冒充服用时间。预设只有显式确认后才能成为本次事实。
5. 独立 journal 可记录并非为助眠而使用的物质；这些事件不自动勾选睡眠记录。关联“助眠扰动”需要用户明确指定，不能根据百科分类推断。
6. 详情入口不暴露最近药名；切换个人/示例档案时清空详情草稿，示例档案不读取个人药物库。

## 存储边界与最小结构

扩展采用独立、按档案隔离的本地 SQLite 文件，例如 `data/private/personal/medication.sqlite3`；现有睡眠 CSV 保持原位置与 schema。仅首次主动保存详情时创建，不为勾选事件生成虚构明细。不需要账号或网络。此处“本地”指服务运行机器的磁盘，并不表示加密或阻止操作系统/用户自己的备份同步。

| 实体 | 最小字段与约束 |
|---|---|
| catalog | UUID 主键、本地显示名；可选真实名称、剂型、备注；归档状态、创建/更新时间。药名不作主键。 |
| journal | UUID 事件主键、可空 catalog 外键、名称快照、可空实际使用日期/时间、时间精度与时区、可空剂量原文/途径/备注、创建时间、修订版本。 |
| sleep_link | 事件 UUID、关联的睡眠录入自然日期、可选区间快照、关联是否待核对。允许一段睡眠关联多次用药，一次用药关联多段睡眠。 |
| reference | catalog UUID、来源名、用户选定的 HTTP(S) URL、来源标识、可选版本/查阅时间。私有代号与外部物质标识分开存储。 |
| metadata | 独立 schema 版本；journal 写入幂等键，防止提交重试重复新增。 |

服用日期、睡眠录入日期、18:00 派生节律日、写入时间是不同字段。只知道关联哪段睡眠时，服用时间仍为空；日期精度的事件不能伪装为某个午夜时间点。剂量允许“半片”等原文，未知道规格不换算 mg，空值不是零剂量。

现有睡眠记录没有稳定 UUID，因此首版只声明日期/区间关联，不能用 DataFrame 行号作外键。修正睡眠区间后将不匹配链接标为待核对，不自动转移到别的记录；以后如引入稳定 sleep UUID，再显式迁移链接。

catalog 与 journal 写入采用事务；更正/删除前使用 SQLite backup API 生成一致备份。个人详情不并入默认 CSV 导出、研究报告、应用日志或外部评估器请求。详情导出/清除应有独立范围；清除操作必须说明旧备份仍可能保留数据。不能把本地日志做成不可删除的永久隐私档案。

## 相图与模型的使用边界

扩展的目的，是给相轨迹增加事件上下文，而不是为了记录完整而收集药物资料。

- 保留全部真实观察点与联合目标函数。标记用药/通宵日期，不把扰动点作为“坏数据”自动删除，也不默认降低权重。
- 区分有标记、未标记、来源默认/未知。没有详细日志的已勾选记录仍是有效事件证据。
- 一条转移同时检查两端及跨越区间的事件，不能只看终点。服用时间未知时仅按关联睡眠展示，不宣称先后顺序。
- 后续比较全样本与事件分层的前向预测；报告覆盖率和样本量。无标记序列不叫“自然/无药”对照。事件后第几天只是历时，不是药物清除时间；布尔标记不足以设置统一洗脱期。
- 助眠药物、通宵及未观测外因都可能参与真实状态变化，也可能改变睡眠中点对内源相位的代表性。不能由交替回摆单独识别这些机制。
- 详细剂量/时间仅在用户愿意记录且样本足够时用于探索性关联；存在因睡不好才用药的选择偏差，不能将事后改善解释成用药因果效应。当前不估计药物响应曲线，不输出用药优化方案，不把百科半衰期变成个人移相系数。

## 外部资料源的选择

首版选择“可选外链”，不接自动检索 API、不整库导入。点击会访问外部站点，但应用不发送私有代号、日期、剂量或日志；外链本身可能透露所查物质。链接不自动预览、不加载第三方图片。以后若做本地公共资料缓存，需单独标明来源、版本及许可，不能与个人使用事实混表。

| 来源 | 项目中的定位 | 本次核实的限制 |
|---|---|---|
| [DailyMed](https://dailymed.nlm.nih.gov/dailymed/about-dailymed.cfm) | 美国药品标签资料入口，适合有明确药品名称时主动查阅。 | 收录在用标签，包括部分未获 FDA 批准产品；在用标签不一定等于最新 FDA 批准标签，也不保证覆盖本地品牌。提供 [REST 服务](https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm)，本项目目前不接入。 |
| [dose.wiki](https://dose.wiki/docs/license) | 可选物质百科链接。 | 自有内容多为 CC0，但交互作用字段、部分媒体等存在不同许可；不能将整份数据集当作统一 CC0。许可证与资料是否适合临床推断是不同问题。 |
| [PsychonautWiki](https://psychonautwiki.org/wiki/Main_Page) | 用户自选补充链接。 | 本次正文请求返回 403，未完成内容及接口契约核验，不据此承诺可稳定接入。 |
| [substance.wiki](https://substance.wiki/) | 暂保留用户自选链接。 | 本次返回标题 Drug.Community，但无可读正文，未核实覆盖范围、接口或许可。 |

不是越全越适合：MRDM 需要可选的查阅来源与真实事件上下文，而不是内置一个剂量推荐引擎。允许用户自行添加其他资料链接，避免个人目录被某个外部站点的覆盖范围限制。

## 实施顺序与必要验证

v1.3 已实现：首次主动保存才创建 SQLite；名称/代号库、可空用量/钟点/备注、关联睡眠自然日期、幂等追加、按需显示本地日志。精确服用日期与时区尚未采集，因此不重建服用时间戳；尚无更正/删除/导出 UI。不会迁移历史或修改睡眠 checkbox。下一步核心研究先利用现有标记做事件分层；目录与 journal 可独立扩展，不以其完成作为相图研究的前置条件。

扩展落地时只验证关键契约：仅勾选不创建详情；离线可用；档案隔离；未知时间/剂量保留为空；重复提交幂等；更名不改历史；更正备份及事务失败回滚；详情不会进入默认导出或网络请求。无需为静态文字扩大测试范围。
